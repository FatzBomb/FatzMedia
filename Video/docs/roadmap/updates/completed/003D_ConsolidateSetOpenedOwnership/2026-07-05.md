# Stage Update — 003D Consolidate SetOpened Ownership

Stage: 003D — Consolidate SetOpened Ownership
Date: 2026-07-05

## Changed

- `FatzBombMedia.MediaControl/Pipeline/AudioPipeline.cs` — added `private bool _ownStateForCurrentOpen = true;` field. Split `Open(string path)` and `Open(IArchiveEntryInfo archiveEntry)` into public delegating overloads (`ownState: true`) and internal `Open(..., bool ownState)` overloads. When `ownState` is `false`, the `SetOpened` call in `Open` and in `OnAudioOpened` is suppressed. `State.Reset()` on failure paths is kept unconditional (harmless — `Close()` already reset). `_sourcePath`, `IsOpen`, and `_pendingOpenPath` tracking are unchanged.

- `FatzBombMedia.MediaControl/Pipeline/PlaybackCoordinator.cs` — `OpenAudioCdg(string, string)` and `OpenAudioCdg(IArchiveEntryInfo, IArchiveEntryInfo)` now call `_session.Audio?.Open(audioPath, ownState: false)` / `Open(audioEntry, ownState: false)`. The coordinator's `State.SetOpened(MediaContent.Audio | MediaContent.Cdg, ...)` call is now the sole `SetOpened` for paired audio+cdg opens.

No public API changed. The new `Open(..., bool ownState)` overloads are `internal` (assembly-scoped), matching `AudioPipeline`'s `internal sealed` visibility.

## Rationale

The 003B mapping (finding 3) identified that paired audio+cdg opens produced three `SetOpened` calls: `OnAudioOpened` (BASS sync, `Audio`-only), `AudioPipeline.Open` (caller thread, `Audio`-only), and `PlaybackCoordinator.OpenAudioCdg` (caller thread, `Audio|Cdg`). The last writer won, but the first two were redundant overwrites that briefly set `Content` to `Audio`-only before the coordinator upgraded it to `Audio|Cdg`.

With this change, for paired opens, `AudioPipeline` opens the engine and tracks `_sourcePath`/`IsOpen` but does not claim `Content`. The coordinator is the sole `SetOpened` writer, establishing clear ownership: pipelines own `SetOpened` for standalone opens, the coordinator owns `SetOpened` for compound (paired) opens.

`_ownStateForCurrentOpen` is set before `Engine.Open` and read by `OnAudioOpened` (which fires synchronously during `Engine.Open`). The `Opened` event only fires from `Engine.Open` methods, so the flag is always correct when the handler runs. The next `Open` call resets the flag.

## Notes

- `CdgPipeline.OpenPaired` still does not call `SetOpened` — it only adjusts `Duration` and `Position`. This is intentional: the coordinator owns `Content` for paired opens.
- `OnAudioClosed` still calls `State.Reset()` unconditionally. This is correct: when the audio engine closes (during `MediaSession.Clear` / `AudioPipeline.Close`), state should be reset regardless of who owned the initial `SetOpened`.
- `OnAudioStateChanged` and `OnAudioPlaybackEnded` write `PlaybackState`/`Position`, not `Content`, so they are unaffected by `ownState`.
