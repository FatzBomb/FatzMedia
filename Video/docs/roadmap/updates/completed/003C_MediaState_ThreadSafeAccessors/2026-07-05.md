# Stage Update — 003C MediaState Thread-Safe Accessors

Stage: 003C — MediaState Thread-Safe Accessors
Date: 2026-07-05

## Changed

- `FatzBombMedia.MediaControl/Pipeline/MediaState.cs` — added a `private readonly Lock _gate = new();` and converted the five auto-properties (`Content`, `PlaybackState`, `SourcePath`, `PositionSeconds`, `DurationSeconds`) to explicit backing fields with lock-guarded getters. All five public mutators (`SetOpened`, `SetPlaybackState`, `SetPosition`, `SetDuration`, `Reset`) now acquire `_gate` before reading or writing the backing fields, including the equality short-circuit checks in `SetPlaybackState` and `SetPosition` and the position-clamp in `SetDuration`.

No public API changed. `MediaState` remains `internal sealed` with the same members. The `Lock` type is `System.Threading.Lock` (already used in `CdgPipeline` and `VideoPipeline`), available unqualified via the project's `ImplicitUsings`.

## Rationale

The 003B mapping identified that `MediaState` is shared by reference across `AudioPipeline`, `CdgPipeline`, and `VideoPipeline`, and is written from at least three threads for video (transport caller thread, seek worker, presentation loop) and from BASS sync threads for audio. The previous setters only had equality short-circuits — no synchronization — so concurrent writers could race on `PlaybackState` and `PositionSeconds`. This stage adds the smallest safe synchronization seam: a single lock guarding all reads and writes. No event threading, no public API, no behavior change beyond making the accessors atomic with respect to each other.

## Validation

- `dotnet build FatzBombMedia.MediaControl/FatzBombMedia.MediaControl.csproj -c Debug --no-restore` — succeeded, 0 warnings, 0 errors.
- `dotnet build FatzBombMedia.sln -c Release --no-restore` — succeeded, 0 warnings, 0 errors (Release treats warnings as errors per AGENTS.md).

No tests exist in this repo. Manual smoke test (per `docs/VALIDATION.md`) is recommended but not required for this change since it is purely additive synchronization with no logic change. The lock is non-reentrant and no `MediaState` method calls another `MediaState` member while holding `_gate`, so there is no deadlock risk. `IsOpen` calls the `Content` getter (which locks) but is never called from within a held lock.

## Notes

- The getters now acquire `_gate` on every read. `MediaState` properties are read on every presentation tick and on every public `State`/`Position`/`Duration` query from `PipelineMediaEngine` / `MediaControlPlayer`. An uncontended `Lock` enter/exit is cheap (tens of nanoseconds on .NET 10), and the previous code already had no synchronization, so this is a strict improvement in correctness with negligible throughput impact. If profiling later shows contention on the presentation path, the lock can be swapped for a `ReaderWriterLockSlim` or the hot read path can be relaxed — but that is speculative and out of scope for this stage.
- The private setters were removed (properties are now get-only with explicit backing fields). No external code wrote to these properties; all writers go through the `Set*` methods, confirmed by the 003B writer table.
