# Stage Update

Stage: 004A — Typed Error Surface
Date: 2026-07-06

Changed:
- Added public `MediaErrorCode` enum (`Api/MediaErrorCode.cs`) with 8 high-value categories: None, Unknown, FileNotFound, NativeLibraryMissing, UnsupportedFormat, OpenFailed, DecodeFailed, InternalError.
- Added public `MediaErrorEventArgs : EventArgs` (`Api/MediaErrorEventArgs.cs`) carrying Code, Message, SourcePath, InnerException.
- Added `event EventHandler<MediaErrorEventArgs>? MediaError` to `IMediaControlSession` and `MediaControlPlayer`.
- Added internal `IMediaErrorSource` interface (`Core/Abstractions/IMediaErrorSource.cs`) and internal `MediaErrorInfo` record (`Core/MediaErrorInfo.cs`) as the Core-internal seam that keeps pipeline internals out of the public contract.
- `PipelineMediaEngine` now implements `IMediaErrorSource` and raises typed errors at high-value failure points:
  - `Open(string path)`: FileNotFound for missing files, UnsupportedFormat for unsupported types, OpenFailed for coordinator open failures.
  - `Open(MediaInputSource source)`: UnsupportedFormat for unknown source kinds.
  - `OpenImageFile`: FileNotFound, OpenFailed (decoder), DecodeFailed (frame decode).
- `MediaControlPlayer` subscribes to `IMediaErrorSource.ErrorOccurred` and re-marshals to the public `MediaError` event through the existing `MediaControlOperationQueue` (same pattern as MediaEnded/MediaStarted/MediaStopped). Unsubscribes in Dispose.
- Added `MediaErrorEventArgsTests` (11 tests) covering construction, null handling, and all defined codes.

Validation:
- Debug build: 0 warnings, 0 errors.
- Release build (warnings-as-errors): 0 warnings, 0 errors.
- All 119 tests pass (108 existing + 11 new).
- WPF adapter boundary check: no new Core pipeline/internal/D3D11 namespaces pulled into the adapter. The `MediaError` event is inherited via the public API — no WPF-side changes needed.

Still open:
- Bootstrap/native-library-load failures still surface only as `InvalidOperationException` from the constructor (no `MediaControlPlayer` exists yet to raise `MediaError`). This is acceptable for the first safe step since the exception already carries `Bootstrap.Message`.
- Internal pipeline `catch` blocks in `PlaybackScheduler`, `CdgPipeline`, `VideoPipeline` (seek workers, loop restarts, DWM timing) still swallow exceptions via `Debug.WriteLine` only. These are lower-value and out of scope for the first safe step.
- `AudioEngine` BASS init failure and normalization analysis failure are still `Debug.WriteLine`-only.
- Device/scheduler loop failures not surfaced (stage explicitly forbids device recovery).
- Targeted open/failure smoke tests (load missing file, load unsupported format) require manual verification via the Player host.

Notes:
- Existing `bool` return values from Load/Play/Pause/Stop/Seek are preserved — the `MediaError` event is additive, not a replacement.
- The `MediaError` event fires from background threads (operation queue); hosts must marshal to the UI thread, consistent with the existing `MediaEnded`/`MediaStarted`/`MediaStopped` events.
- No per-frame or per-decode raise points were added (stage explicitly forbids noisy logging).
