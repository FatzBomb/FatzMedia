# 012A.2 — Shared Demuxer / Input Layer: Staged Implementation Plan

Parent: `docs/roadmap/012A_FUTURE_SharedDemuxerInputLayer.md`
Mapping: `docs/roadmap/012A_NOTE_SharedDemuxerInputLayerMap.md`

This document turns the §8 risks in the mapping note into a **staged, buildable,
behavior-preserving** implementation plan. It does **not** authorize source
edits by itself. Each sub-stage below is a separate `implement-stage` unit with
its own validation gate and stop conditions.

## Revision history

- **2026-07-09 (original):** S0→S5 plan with S3 (shared cursor) and S4 (unified
  seek) as separate sub-stages.
- **2026-07-09 (revised):** S1 and S2 completed and smoke-tested clean. S3
  attempted, passed automated gates, but **reverted** after manual smoke
  revealed two critical regressions (gapless loop freeze, AV1 seek freeze).
  Root cause: a single `av_read_frame` cursor inherently couples seek positions,
  breaking the independent seek semantics that gapless loop and SmartSeek depend
  on. **S3 (shared cursor) and S4 (unified seek) cannot be separated** — they
  are now merged into a single sub-stage. See §Lessons learned from S3 revert.

## Activation preconditions (from parent "Not Active Until")

Do **not** start source edits until all are confirmed stable:

- [x] Error reporting stable (diagnostics routing not mid-refactor).
- [x] Device handling stable (hardware decode fallback + device-lost recovery
      not being changed concurrently — see `SwapVideoDecoder`,
      `VideoPipeline.cs:1393`).
- [x] State ownership stable (`MediaState` / pipeline ownership settled).
- [x] Working tree clean (commit first — this is a multi-file architectural change).

All preconditions were met for S1/S2. They remain met for the revised S3.

## Design principle: seam-first, switch-over-last

The rewrite is sequenced so **every sub-stage is reversible and behavior-preserving
until the final switch-over**. A `MediaDemuxer` type was introduced *behind*
the existing engines, proven byte-identical, then adopted one consumer at a time.

**Critical lesson (learned from S3 revert):** "behavior-preserving" does **not**
mean "shared cursor without unified seek." Sharing the `av_read_frame` cursor
inherently changes seek behavior because the codebase's loop/seek semantics
require **independent** seek positions per consumer. The shared cursor and
unified seek semantics must be introduced **together** — they are one atomic
change, not two.

Non-goals for the whole of 012A.2 (deferred to later stages, per parent + true
non-goals): subtitles (013A), multi-track/chapters, streaming/network (014A),
folding BASS-pull audio-only or CDG sidecar into the FFmpeg demux.

## S3 (original) — Shared read cursor with per-stream fan-out (REVERTED)

**Status: REVERTED.** Attempted 2026-07-09. Passed automated gates (0 warnings,
183 tests, boundary/parity scripts) but manual smoke revealed two critical
regressions. Source reverted to S2 state. See
`docs/roadmap/updates/012A_S3/StageUpdate.md` and
`docs/roadmap/012A_S3_BACKLOG_SharedReadCursor.md`.

### What was tried

A `SharedDemuxer` wrapping `MediaDemuxer` with per-stream `Queue<IntPtr>` packet
queues, per-stream EOF flags, `ReadVideoPacket`/`ReadAudioPacket` (dispatch
non-matching packets to the other queue), `SeekVideo`/`SeekAudio` (flush only
the requesting stream's queue + clear its EOF flag). Both engines in
`VideoPipeline.Open` shared one instance.

### Bugs found in smoke

1. **Gapless loop freeze at boundary.** `TryPreSeekLoopStart` pre-seeks the
   video decoder to 0 while audio is still playing buffered audio near EOF. With
   the shared cursor, this video pre-seek moves the **single** `av_read_frame`
   cursor to 0, disrupting audio's read position. Audio either sees EOF
   prematurely (because `ReadVideoPacket` set `_audioEof=true` when video hit
   EOF, and `SeekVideo` didn't clear it), causing an early wrap, or reads
   packets from position 0 instead of near EOF.

2. **AV1 software seek freeze.** `SeekCore` calls `SeekAudio` then `SeekVideo`
   on the same cursor. The second seek overrides the first. Audio's next read
   gets packets from the video-seeked position, not the audio-seeked position.

### Root cause

A single `av_read_frame` cursor inherently couples seek positions. The
codebase's seek/loop semantics require **independent** seek positions per
consumer:
- Video-flexible SmartSeek (video may show nearby frame, audio hits exact target).
- Gapless loop (video pre-seeks to 0 while audio continues reading near EOF).

This is exactly the §8.2 risk from the mapping note: "Independent seek
semantics." The original plan assumed S3 could be behavior-preserving without
S4 — **this assumption was wrong.** Sharing the cursor changes seek behavior by
definition.

### Lessons learned

1. **S3 (shared cursor) and S4 (unified seek) are one atomic change, not two.**
   The shared cursor only works if seek semantics are unified in the same
   patch. They cannot be sequenced separately.

2. **Per-stream EOF propagation is dangerous.** Setting `_audioEof=true` when
   video hits EOF assumes audio will also hit EOF imminently — but with
   buffered audio, audio may not read from the demuxer for seconds. The EOF
   flag must be per-consumer-read, not cross-stream-propagated.

3. **`SeekVideo`/`SeekAudio` on a shared cursor is fundamentally broken.** Two
   seeks on the same `av_seek_frame` context means the second one wins. The
   only way to have independent seek positions with one cursor is to **not
   seek the container at all** for one consumer (e.g., the gapless loop case
   where audio wraps its own decoder) and coordinate the other consumer's seek
   with the first consumer's buffered state.

## S3 (revised) — Shared cursor + unified seek semantics (DESIGN-GATED)

**Status: NOT STARTED.** This is the merged S3+S4. It requires a design note
before any source edits.

**Goal:** Collapse to one `SharedDemuxer` instance whose single
`av_read_frame` cursor fans packets into independent per-stream queues, **and**
unify seek semantics so one container seek satisfies all consumers without
breaking gapless loop or SmartSeek.

### Why this is one sub-stage, not two

The S3 revert proved that sharing the cursor without unifying seek semantics
breaks both gapless loop and SmartSeek. The two concerns are inseparable:
- Shared cursor → one seek position → must reconcile video-flexible vs
  audio-exact vs gapless-loop in the same patch.
- Unified seek → only meaningful when there's one cursor to seek.

### Design challenges (must be resolved before source edits)

1. **Coordinated seek.** `SeekCore` currently calls `SeekAudio` then `SeekVideo`
   — two independent container seeks to the same target. With one cursor, there
   is one `av_seek_frame`. The design must:
   - Seek the shared cursor once to the target.
   - Flush both per-stream packet queues.
   - Clear both per-stream EOF flags.
   - Set both `_discardFramesBeforeSeconds` and `_discardAudioBeforeSeconds`
     (each consumer drops packets before the target independently).

2. **Gapless loop: video pre-seek vs audio autonomy.** This is the hardest
   problem. Today:
   - `TryPreSeekLoopStart` seeks the video decoder to 0 while audio is still
     playing buffered audio near EOF (proactive, gapless).
   - `VideoAudioEngine.WrapDecoderForLoop` seeks the audio decoder to 0 at EOF
     without stopping the BASS channel (gapless audio wrap).
   - `CommitAudioLoopWrap` catches the video side up with no audio calls.

   With a shared cursor, video's pre-seek to 0 would move the cursor away from
   audio's read position. **The design must either:**
   - **(a)** Not pre-seek the shared cursor for video; instead, buffer enough
     video packets from position 0 *before* the loop boundary by reading ahead
     while audio is still consuming near-EOF packets. This requires the fan-out
     queue to hold both tail (near-EOF) and head (position-0) video packets
     simultaneously, with the presentation layer selecting from the right range.
   - **(b)** Keep two demuxer instances for the loop case only (shared for
     normal playback, split for loop wrap). This is complex and fragile.
   - **(c)** Accept a non-gapless video restart at the loop boundary (audio
     stays gapless via BASS push buffer; video seeks the shared cursor to 0
     after audio wraps). This degrades the loop experience but is safe.
   - **(d)** Some hybrid: the shared cursor stays at EOF until audio wraps,
     then seeks to 0 for both. Video presentation freezes for the brief seek
     gap (like the old `TryRestartLoopPlayback` reactive path).

   **Option (d) is likely the safest** — it preserves gapless audio (the BASS
   channel never stops) and accepts a brief video freeze at the loop boundary
   (which the old reactive fallback already did). The proactive video pre-seek
   (`TryPreSeekLoopStart`) would be removed or deferred to S5.

3. **Per-stream EOF.** EOF must be per-consumer-read, not cross-stream-propagated.
   When video hits EOF, do NOT set `_audioEof` — audio will discover EOF on its
   own next read. When audio hits EOF, do NOT set `_videoEof`. Each consumer's
   EOF is independent.

4. **`SwapVideoDecoder` / device-lost recovery.** The shared demuxer must
   survive a video-decoder rebuild. `SwapVideoDecoder` disposes and recreates
   the `VideoDecoder` but must NOT dispose the shared demuxer. The new decoder
   re-attaches to the existing shared demuxer at the current position. Audio
   keeps running undisturbed.

5. **Hardware probe.** `HardwareDecodeDeviceAvailable` opens a throwaway
   `VideoDecoder` to test the D3D11 device. This must continue to use its own
   separate demuxer (not the shared one) — it's a transient probe that must not
   disturb the live read cursor.

### Proposed approach (high-level, needs a design note)

- `SharedDemuxer` with per-stream packet queues (as attempted in original S3).
- **Single `Seek(target)`** that seeks the container once, flushes both queues,
  clears both EOFs. No `SeekVideo`/`SeekAudio` split.
- **Per-consumer EOF** (no cross-stream propagation).
- **Gapless loop via option (d):** remove `TryPreSeekLoopStart`'s shared-cursor
  pre-seek; let audio wrap autonomously; video seeks the shared cursor to 0
  when `CommitAudioLoopWrap` fires (reactive, not proactive). Accept brief
  video freeze at loop boundary.
- `SwapVideoDecoder` passes the existing shared demuxer to the new decoder.

### Validation

Debug + Release (0 warnings) + boundary/parity scripts + **full** manual smoke:
- Video-with-audio playback (H.264+AAC, HEVC HW, AV1 SW, AVI).
- A/V sync.
- Seek (rapid scrubbing — preview + settle).
- **Gapless audio-backed loop** (the critical test).
- Device-lost recovery (`SwapVideoDecoder` reuses shared demuxer).
- Background video (own SharedDemuxer, unaffected).
- CDG-paired, media switch, extended soak (10+ min).

### Stop conditions

- Any starvation/overflow (audio dropouts, video stalls) → revert to S2.
- Any regression in `SwapVideoDecoder` / device-lost recovery → revert.
- Any audio gap at loop boundary → revert.
- Any A/V desync after seek → revert.

### Prerequisite

A **design note** must be written and reviewed before source edits. The design
note must resolve all five challenges above and specify the exact gapless-loop
strategy chosen. Do not promote to BACKLOG until the design note exists.
