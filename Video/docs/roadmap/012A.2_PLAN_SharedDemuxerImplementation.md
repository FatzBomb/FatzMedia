# 012A.2 — Shared Demuxer / Input Layer: Staged Implementation Plan

Parent: `docs/roadmap/012A_FUTURE_SharedDemuxerInputLayer.md`
Mapping: `docs/roadmap/012A_NOTE_SharedDemuxerInputLayerMap.md`

This document turns the §8 risks in the mapping note into a **staged, buildable,
behavior-preserving** implementation plan. It does **not** authorize source
edits by itself. Each sub-stage below is a separate `implement-stage` unit with
its own validation gate and stop conditions.

## Activation preconditions (from parent "Not Active Until")

Do **not** start §S1 source edits until all are confirmed stable:

- [ ] Error reporting stable (diagnostics routing not mid-refactor).
- [ ] Device handling stable (hardware decode fallback + device-lost recovery
      not being changed concurrently — see `SwapVideoDecoder`,
      `VideoPipeline.cs:1393`).
- [ ] State ownership stable (`MediaState` / pipeline ownership settled).
- [ ] Working tree clean (commit first — this is a multi-file architectural change).

If any is unchecked, stop and hold at the mapping note.

## Design principle: seam-first, switch-over-last

The rewrite is sequenced so **every sub-stage is reversible and behavior-preserving
until the final switch-over**. A new `MediaDemuxer` type is introduced *behind*
the existing engines, proven byte-identical, then adopted one consumer at a time.
No sub-stage both introduces the shared read cursor **and** changes seek/loop
semantics — those are deliberately separated (the §8.2 hazard).

Non-goals for the whole of 012A.2 (deferred to later stages, per parent + true
non-goals): subtitles (013A), multi-track/chapters, streaming/network (014A),
folding BASS-pull audio-only or CDG sidecar into the FFmpeg demux.

## S0 — Baseline capture (no source change)

**Goal:** Establish the "identical behavior" oracle before touching anything.

- Capture, on 3–4 representative files (H.264+AAC mp4, HEVC hardware, AV1
  software, AVI with interleaved audio): decoded video frame PTS sequence,
  pushed audio frame count + end-position sequence, seek-to-target results
  (preview + settle), and gapless-loop wrap positions.
- Record from existing verbose logging (`EnableVerboseLogging`) — no new code.

**Validation:** docs/data only; no build.
**Stop condition:** if current logging can't produce a stable oracle, add a
minimal opt-in trace in S1 rather than guessing.

---

## S1 — Introduce `MediaDemuxer` behind `VideoDecoder` (no behavior change)

**Goal:** Extract container-open + video packet read into a new internal
`MediaDemuxer`, used **only** by `VideoDecoder`. Audio untouched. Output
identical.

**Touch list (proposed):**
- New `FatzBombMedia.MediaControl/Core/Media/MediaDemuxer.cs` (internal, unsafe):
  owns one `AVFormatContext`, `avformat_open_input` + `find_stream_info`, stream
  discovery, and `av_read_frame` into a caller-provided packet. Exposes
  per-stream index metadata and a `ReadNextPacket(out streamIndex)` primitive.
- `VideoDecoder.cs`: replace its inline `_fmt` open/read (`:34, 103-155, 157-184`)
  with delegation to `MediaDemuxer`, keeping the exact same video-only behavior
  (still discard non-video streams; still one reusable packet). **No signature
  changes to `VideoDecoder`'s public/internal surface.**

**Must not change:** frame PTS output, HW/SW selection, duration derivation,
seek behavior, `discard`-non-video-streams optimization.

**Validation (per working notes — renderer/timing/media behavior/native lifetime):**
Debug + Release (0 warnings) + boundary/parity scripts + manual smoke on the S0
oracle files. Video frame PTS sequences must match S0 byte-for-byte.
**Stop condition:** any PTS/duration/HW-path divergence from S0 → revert, do not
proceed.

---

## S2 — Route `VideoAudioEngine` reads through a *second, independent* `MediaDemuxer`

**Goal:** Prove `MediaDemuxer` also serves audio — but still as **two separate
demuxer instances** (two format contexts, two cursors). Still no shared cursor.
This isolates "does the demuxer abstraction fit audio?" from "can they share one
cursor?"

**Touch list (proposed):**
- `VideoAudioEngine.cs`: replace inline `_formatContext` open/read
  (`:21, 247-291, 320-369`) with its own `MediaDemuxer` instance. Preserve the
  per-call packet semantics behavior, audio discard/prebuffer/throttle exactly
  (`_discardAudioBeforeSeconds`, `PrebufferAudio`, watermarks — mapping §5).

**Must not change:** BASS push/tempo path, audio positions, throttle timing,
gapless-loop wrap (`WrapDecoderForLoop`, `:375`).

**Validation:** Debug + Release + scripts + manual smoke (A/V sync, tempo ±20%,
seek, gapless loop, CDG-paired). Audio frame-count/end-position and loop-wrap
sequences must match S0.
**Stop condition:** any A/V sync, throttle, or loop-wrap divergence → revert.

> After S2 the codebase is functionally identical to today but both engines sit
> on the same demuxer *type*. This is a safe landing point — 012A.2 may pause
> here indefinitely.

---

## S3 — Shared read cursor with per-stream fan-out queues (behavior-preserving)

**Goal:** Collapse to **one** `MediaDemuxer` instance whose single
`av_read_frame` cursor fans packets into **independent per-stream packet queues**
(video queue, audio queue) with per-stream backpressure. Consumers drain their
own queue at their own rate (mapping §8.1).

**Design constraints:**
- Independent backpressure: video queue bounded by frame target; audio queue
  bounded by the 4s/2s push watermark logic (mapping §5). One full consumer must
  **not** block the other — the demuxer buffers a bounded number of the other
  stream's packets ahead.
- Single reader thread ownership: the existing `DecodeLoop`
  (`VideoPipeline.cs:1238`) drives one `ReadNext` that dispatches to whichever
  queue is hungry; decode of each stream stays on its current path.
- Ownership/lifetime of queued `AVPacket*` clearly defined (ref/unref rules,
  drain-on-seek, drain-on-close).

**Explicitly NOT in S3:** seek-semantics unification (still two seeks on the one
context — see S4) and loop changes. S3 changes *how packets are read and
buffered*, not *how seek/loop behave*.

**Validation:** Debug + Release + scripts + **full** manual smoke (this is the
highest-risk sub-stage). Compare all four S0 sequences. Extended soak: long
playback, rapid scrub, media switch, device-lost recovery, gapless loop.
**Stop conditions:**
- Any starvation/overflow (audio dropouts, video stalls) → revert.
- Any regression in `SwapVideoDecoder` / device-lost recovery (S3 must keep the
  demuxer alive across a video-decoder rebuild — mapping §8.3) → revert.

---

## S4 — Unify seek onto the shared cursor (the hard part)

**Goal:** Make one container seek satisfy video-flexible SmartSeek **and**
audio-exact discard **and** gapless-loop independence (mapping §4, §8.2).

**Design must reconcile:**
- Video's `_discardFramesBeforeSeconds` vs audio's `_discardAudioBeforeSeconds`
  from a single seek cursor.
- Video-flexible SmartSeek (video may stay frozen / show nearby frame) while
  audio/CDG/clock hit the exact target.
- Gapless loop: audio wrapping its own decode independently must survive — a
  shared seek must **not** be forced at the loop boundary
  (`CommitAudioLoopWrap`, `:414`; `TryPreSeekLoopStart`, `:1717`).

This sub-stage likely needs its own design note before edits; treat S4 design as
a gate.

**Validation:** Debug + Release + scripts + full manual smoke focused on seek
feel (preview + settle, long-GOP), A/V sync after seek, gapless loop across
boundary, seek during device-lost recovery.
**Stop conditions:** any seek-feel regression, A/V desync after seek, or audio
gap at loop boundary → revert to S3 (which is a stable landing point).

---

## S5 — Cleanup, archive temp-file dedupe, docs

**Goal:** Remove now-dead per-engine open/read code paths (only after S3/S4 prove
the shared path); collapse the double archive temp-file materialization into one
(mapping §8.6); update `docs/CURRENT_ARCHITECTURE.md`.

**Guardrail:** dead-code removal only after whole-repo search (reflection, DI,
XAML, `nameof`, resource lookups) per the deletion guardrail. Prefer in-place
edits over delete-and-recreate.

**Validation:** Debug + Release + scripts + smoke. Archive/CDG workflows
explicitly re-tested (Must Not Break).

## Cross-cutting Must-Not-Break checklist (every sub-stage)

- [ ] BASS tempo/pitch push path unchanged (`CreateBassStreams`, `:688`).
- [ ] Video-with-audio sync (`AudioPresentationClock` origin) unchanged.
- [ ] Seek preview/settle feel unchanged.
- [ ] CDG/archive/sidecar workflows unchanged.
- [ ] Hardware decoder fallback + device-lost recovery unchanged
      (`SwapVideoDecoder` must keep working across a live demuxer).
- [ ] Gapless audio-backed loop unchanged (no forced shared seek at EOF).
- [ ] WPF adapter boundary untouched (Core-only change).

## Recommended promotion order

`S0` (data) → `S1` → `S2` → **stable landing** → `S3` → `S4` (design-gated) →
`S5`. Promote one sub-stage at a time by copying it into a `BACKLOG` stage file;
do not run more than one sub-stage per `implement-stage` session given the risk.
